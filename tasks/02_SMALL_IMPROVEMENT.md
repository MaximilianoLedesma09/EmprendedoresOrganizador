
# Mejoras pequeñas

Analizar el proyecto y proponer cinco mejoras pequeñas y de bajo riesgo.

Para cada una explicar:
- Problema.
- Evidencia.
- Beneficio.
- Archivos afectados.
- Riesgos.
- Pruebas.
- Forma de revertir.

Recomendar una mejora.

No escribir código hasta que el Tech Lead elija y autorice una propuesta.

Implementar exclusivamente el cambio aprobado.

Al terminar, mostrar el diff y los resultados de las pruebas.

Esperar revisión.
